# 메시지 유형별 처리 및 특정 클라이언트 전송

**현재 프로젝트(sync-server)** 기준으로, WebSocket 메시지 타입별 처리 방식과 `targetClientId`·`clientId`·`clientKey` 동작을 정리한 문서입니다.

- **처리 진입점**: `server/src/handlers.js` → `handleMessage(data, ws, roomId)`
- **메시지 수신**: `server/src/index.js` → JSON 파싱 후 `newClient`일 때 `attachUserInfo(ws, data)` 호출, 이어서 `handleMessage(data, ws, ws.roomId)` 호출

## 1. 메시지 타입 요약

| type | 방향 | 처리 요약 |
|------|------|-----------|
| `newClient` | 클라이언트 → 서버 | Room 가입/이동, `clientKey` 중복 시 4000 거부, **신규 입장자에게만** `roomState` 전송, Room 내 다른 클라이언트에게 `newClient` 브로드캐스트 |
| `chat` | 클라이언트 → 서버 | `relayToRoom`: `targetClientId` 있으면 해당 1명에게만, 없으면 Room 전체 브로드캐스트 |
| `broadcast` | 클라이언트 → 서버 | 위와 동일. `value.event`가 `movePage`/`setForm`이면 Room 상태 저장(신규 입장자 동기화용) |
| `broadcastAll` | 클라이언트 → 서버 | `relayToRoom` (targetClientId / Room 브로드캐스트) |
| `request` | 클라이언트 → 서버 | `relayToRoom` |
| `response` | 클라이언트 → 서버 | `relayToRoom` |
| `clientList` | 클라이언트 → 서버 | **요청한 클라이언트 1명에게만** `clientList` 응답 전송 |
| **그 외** | 클라이언트 → 서버 | `relayToRoom` (알 수 없는 타입도 그대로 릴레이) |
| `roomState` | 서버 → 클라이언트 | 서버가 **신규 입장자에게만** 전송 (클라이언트가 보내는 타입 아님) |
| `clientLeft` | 서버 → 클라이언트 | 클라이언트 연결 종료 시 서버가 **Room 내 나머지 클라이언트에게** 자동 전송 |

## 2. 클라이언트 → 서버: 타입별 처리

### 2.1. newClient

- **역할**: 특정 Room 입장(또는 Room 이동). 서버가 부여한 `clientId`를 Room 내 다른 클라이언트에게 알림.
- **필수**: `roomId`
- **선택**: `user`(clientList용 사용자 정보), `clientKey`(동일 기기 식별, 중복 입장 제어)

**서버 동작** (`handleNewClient`):

1. `roomId` 없으면 경고 로그 후 종료.
2. **Room 이동** 시: 이전 Room에서 `leaveRoom`, 새 Room으로 `joinRoom`.
3. **clientKey**가 있으면:
   - `ws.clientKey`에 저장.
   - 같은 Room 안에 **동일 clientKey를 가진 다른 연결**이 이미 있으면, **새 연결을 4000 코드로 거부** (`Duplicate client in same room (same clientKey)`).
4. `ws.roomId = rid`, `joinRoom(rid, ws)`.
5. **신규 입장자에게만** `roomState` 메시지 전송 (해당 Room의 `lastPage`·`formValues` 등). 기존 참가자에게는 보내지 않음.
6. Room 내 **다른 클라이언트에게** `newClient` 브로드캐스트 (서버가 `data.clientId = ws.clientId`를 넣어 전송).

**수신자**: Room 내 **발신자 제외** 모든 클라이언트 + (roomState는) **입장한 클라이언트 1명**.

---

### 2.2. chat, broadcast, broadcastAll, request, response

- **역할**: Room 단위 릴레이. `targetClientId`가 있으면 한 명에게만, 없으면 Room 전체 브로드캐스트.
- **공통 처리**: `relayToRoom(data, ws, roomId)`.

**서버 동작** (`relayToRoom`):

1. `roomId`(또는 `ws.roomId`) 없으면 경고 로그 후 종료.
2. **targetClientId 존재**  
   → `sendToClient(data.targetClientId, data)` 만 호출 (Room 브로드캐스트 없음).
3. **targetClientId 없음**  
   → `broadcastToRoom(rid, data, ws)` (발신자 제외 Room 전체).  
   추가로 `type === 'broadcast'` 이고 `value.event`가 `movePage` 또는 `setForm`이면 `updateRoomState(rid, data)` 호출 → 신규 입장자용 Room 상태 저장.

**수신자**:
- `targetClientId` 있음: 해당 `clientId` 1명.
- 없음: Room 내 발신자 제외 전체.

---

### 2.3. clientList

- **역할**: 현재 Room 참가자 목록을 **요청한 클라이언트에게만** 응답.
- **서버 동작** (`sendClientList`):
  - 해당 Room의 `getRoomClients(roomId)`로 클라이언트 목록 수집.
  - `readyState === 1`인 클라이언트만 세고, `userInfo`가 있으면 `users` 배열에 포함.
  - `{ roomId, type: 'clientList', users }` 형태로 **요청한 ws 1명에게만** `ws.send()`.

**수신자**: **clientList를 보낸 클라이언트 1명**.

---

### 2.4. 그 외 타입 (default)

- **역할**: 알 수 없는 `type`도 그대로 릴레이 (호환성 유지).
- **서버 동작**: `handleDefault` → `relayToRoom(data, ws, roomId)` (위와 동일: targetClientId / Room 브로드캐스트).

## 3. 서버 → 클라이언트: 자동 전송 메시지

클라이언트가 보내지 않고, **서버가 상황에 따라** 보내는 메시지입니다.

| 메시지 | 시점 | 수신자 | 내용 예시 |
|--------|------|--------|-----------|
| **roomState** | `newClient` 처리 직후 | **신규 입장한 클라이언트 1명** | `{ type: 'roomState', roomId, lastPage?, formValues }` — 해당 Room의 현재 페이지·폼 값 등 |
| **clientLeft** | 클라이언트 연결 종료 시 (`onClose`) | **해당 Room 내 나머지 클라이언트** | `{ type: 'clientLeft', clientId, roomId, userInfo?, timestamp }` |
| **newClient** (브로드캐스트) | `newClient` 처리 시 | **Room 내 다른 클라이언트 전체** | 클라이언트가 보낸 newClient 페이로드 + 서버가 넣은 `clientId` |
| **clientList** | `clientList` 요청에 대한 응답 | **요청한 클라이언트 1명** | `{ type: 'clientList', roomId, users }` |

## 4. clientId / clientKey

### clientId

- **부여 시점**: WebSocket 연결 수립 시, 서버가 `index.js`에서 `ws.clientId = generateClientId()` 로 **서버가 생성**.
- **전달 시점**: `newClient` 처리 시, 서버가 `data.clientId = ws.clientId`를 넣어 Room 내 다른 클라이언트에게 브로드캐스트하므로, **다른 클라이언트는 이 clientId로 해당 참가자를 구분**할 수 있음.
- **용도**: `clientList` 응답·`targetClientId` 지정·`clientLeft` 알림 등에서 “어느 연결인지” 식별.

### clientKey

- **제공**: 클라이언트가 **newClient 메시지**에 `clientKey`를 넣어 전송 (예: 동일 기기/앱 인스턴스 식별자).
- **저장**: 서버는 `ws.clientKey = data.clientKey` 로 보관.
- **용도**: **같은 Room 안에서 동일 clientKey를 가진 기존 연결이 있으면**, 새로 들어오려는 연결을 **4000 코드로 거부** (한 기기당 Room 내 하나의 연결만 허용하는 정책).

## 5. 특정 클라이언트 전송 (targetClientId)

### 개요

- **기본**: `chat`·`broadcast`·`broadcastAll`·`request`·`response` 및 default 릴레이는 **Room 전체** 브로드캐스트(발신자 제외).
- **옵션**: 메시지에 **targetClientId**를 넣으면, 해당 `clientId`를 가진 **한 클라이언트에게만** 전송.

### 구현 위치

| 구분 | 파일 | 내용 |
|------|------|------|
| 단일 전송 | `server/src/rooms.js` | `sendToClient(clientId, message)` — 모든 Room을 돌며 해당 clientId WebSocket에만 전송 |
| 분기 | `server/src/handlers.js` | `relayToRoom` 내부에서 `data.targetClientId` 존재 시 `sendToClient`, 없으면 `broadcastToRoom` |

### 적용 타입

`chat`, `broadcast`, `broadcastAll`, `request`, `response`, 그리고 **알 수 없는 타입(default)** 에서 호출하는 `relayToRoom` 모두 동일 규칙.

### 클라이언트 사용 예

특정 클라이언트에게만 보내려면 기존 메시지에 `targetClientId`만 추가:

```json
{
  "type": "chat",
  "targetClientId": "client_2_1739123456789",
  "value": { "text": "귀하에게만 보내는 메시지" }
}
```

- `targetClientId`를 **생략**하면 기존처럼 Room 전체 브로드캐스트.

## 6. Room 상태 동기화 (roomState)

- **목적**: `broadcast`의 `movePage`·`setForm` 이벤트를 Room별로 저장해 두고, **새로 입장한 클라이언트**가 현재 페이지·폼 값을 한 번에 받을 수 있게 함.
- **저장**: `server/src/roomState.js` — `updateRoomState(roomId, data)` 가 `broadcast` + `movePage`/`setForm` 일 때만 호출됨 (`handlers.js`의 `relayToRoom`에서 호출).
- **전달**: `newClient` 처리 시 `getRoomState(roomId)`로 payload를 만들어 **신규 입장자 1명에게만** `{ type: 'roomState', ...payload }` 전송. 기존 참가자에게는 보내지 않음.
- **정리**: Room 인원이 바뀌어도 기존 릴레이/브로드캐스트에는 관여하지 않고, “입장 시점의 스냅샷”만 제공.

## 7. 흐름 요약

1. **연결**  
   서버가 `ws.clientId` 부여.

2. **입장**  
   클라이언트가 `newClient` (roomId, 선택 user/clientKey) 전송  
   → 서버: clientKey 중복 시 4000 거부 / Room 가입 → **신규 입장자에게만 roomState** → Room 내 다른 클라이언트에게 **newClient(clientId 포함)** 브로드캐스트.

3. **일반 메시지**  
   클라이언트가 `chat`·`broadcast`·`request` 등 전송  
   → 서버: `relayToRoom`  
   - `targetClientId` 있음 → **해당 1명에게만** `sendToClient`  
   - 없음 → **Room 전체** `broadcastToRoom` (발신자 제외).  
   - `broadcast` + movePage/setForm → `updateRoomState` 로 Room 상태 갱신.

4. **참가자 목록**  
   클라이언트가 `clientList` 전송  
   → 서버: **요청한 클라이언트 1명에게만** `clientList` 응답.

5. **퇴장**  
   연결 종료 시 서버가 `onClose`  
   → 해당 Room 내 **나머지 클라이언트에게** `clientLeft` 브로드캐스트 후 `leaveRoom`.
